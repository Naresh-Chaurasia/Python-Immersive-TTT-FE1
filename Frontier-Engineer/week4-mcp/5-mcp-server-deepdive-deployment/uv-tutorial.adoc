= uv Tutorial for Beginners
:toc:
:toclevels: 2
:icons: font
:source-highlighter: highlight.js

`uv` is a fast, all-in-one Python package and project manager (written in
Rust, by Astral) that replaces `pip`, `venv`, `pip-tools`, and `poetry`
with a single tool. This tutorial covers the commands you'll actually use
day-to-day, in the order you'd naturally learn them.

== 1. Check Installation

[source,bash]
----
which uv
uv --version
----

If not installed: `brew install uv` (macOS) or see https://docs.astral.sh/uv/.

== 2. Start a New Project

`uv init` scaffolds a new project with `pyproject.toml`, a starter
`main.py`, `.python-version`, and git files.

[source,bash]
----
uv init my-project      # creates a new folder "my-project"
cd my-project
uv init                 # or run inside an existing empty folder
----

This is exactly how projects like `5-mcp-server-deepdive-deployment` in
this repo were bootstrapped.

== 3. Virtual Environments

A virtual environment is an isolated Python install so one project's
packages never clash with another's.

[source,bash]
----
uv venv                              # creates .venv/ using default Python
uv venv .venv_my_custom_name         # custom env folder name
uv venv --python 3.12                # pin a specific Python version
----

NOTE: You rarely need to run `uv venv` manually -- `uv sync` and `uv run`
create/manage it automatically. Manual `uv venv` is useful when you want a
custom-named environment or to inspect it directly.

== 4. Add Dependencies

`uv add` installs a package **and** records it in `pyproject.toml` +
`uv.lock` in one step (replaces `pip install` + manually editing
requirements files).

[source,bash]
----
uv add requests                # add a plain dependency
uv add "mcp[cli]"              # add with an extra (optional feature set)
uv add "mcp[cli]<2"            # pin a version constraint
----

Compare to this project's `pyproject.toml`:
[source,toml]
----
dependencies = [
    "mcp[cli]>=1.9.0",
]
----
That line was generated by running `uv add "mcp[cli]>=1.9.0"`.

== 5. Install / Sync Dependencies

`uv sync` reads `pyproject.toml` + `uv.lock` and makes your `.venv/`
match exactly -- installing anything missing.

[source,bash]
----
uv sync
----

Run this after cloning a repo, or after someone else changed
`pyproject.toml`.

== 6. Lock File Management

`uv.lock` pins the *exact* resolved version of every dependency (and
sub-dependency) so builds are 100% reproducible on any machine -- the
`uv` equivalent of `package-lock.json`. You normally don't edit it by
hand.

[source,bash]
----
uv lock                              # re-resolve and update uv.lock
uv lock --upgrade-package mcp        # upgrade just one package
----

== 7. Run Code Inside the Project

`uv run <cmd>` executes `<cmd>` using the project's virtual environment
automatically -- no need to `source .venv/bin/activate` first.

[source,bash]
----
uv run python client.py              # run a script
uv run python -c "import mcp; print('OK')"   # run inline code
uv run mcp-server                    # run a console-script command
                                      # (defined under [project.scripts])
----

=== Useful `uv run` flags

[cols="1,3", options="header"]
|===
| Flag | What it does

| `--frozen`
| Use the lock file exactly as-is, skip re-resolving dependencies (faster,
useful in CI or quick one-off checks).

| `--with "mcp[cli]"`
| Temporarily add a package for this run only, without touching
`pyproject.toml` -- handy for a quick test.

| `--directory <path>`
| Run as if you were in `<path>`, without `cd`-ing there first.
|===

[source,bash]
----
uv run --frozen --with "mcp[cli]" python -c "import mcp; print(mcp.__version__)"
uv run --directory /path/to/project --frozen mcp run weather.py
----

== 8. pip-Compatible Interface

`uv` also ships a drop-in `pip`-style interface for cases where you need
raw pip behavior (e.g. inspecting an already-installed package):

[source,bash]
----
uv pip --version
uv pip install -r requirements.txt
uv pip show langchain
----

== 9. Global Tools

`uv tool` installs and runs standalone CLI tools (like `pipx`) in their
own isolated environments, without polluting any project.

[source,bash]
----
uv tool list          # see installed tools
uv tool dir           # where tool environments live
----

== 10. Building for Distribution

`uv build` packages your project into installable artifacts.

[source,bash]
----
uv build
----

Produces `dist/*.whl` (wheel) and `dist/*.tar.gz` (source distribution) --
files you could `pip install` or upload to PyPI.

== Quick Reference Cheat Sheet

[cols="1,2", options="header"]
|===
| Command | Purpose

| `uv init`
| Scaffold a new project

| `uv venv`
| Create a virtual environment manually

| `uv add <pkg>`
| Add + install a dependency

| `uv sync`
| Install everything from `pyproject.toml`/`uv.lock`

| `uv lock`
| Re-resolve/update `uv.lock`

| `uv run <cmd>`
| Run a command inside the project's venv

| `uv pip <args>`
| pip-compatible commands

| `uv tool <args>`
| Manage global standalone CLI tools

| `uv build`
| Package project into `.whl`/`.tar.gz`

| `uv --version`
| Check the installed uv version
|===

== Typical Beginner Workflow

[source,bash]
----
uv init my-mcp-server && cd my-mcp-server   # 1. scaffold project
uv add "mcp[cli]"                           # 2. add dependencies
uv sync                                     # 3. install into .venv/
uv run python main.py                       # 4. run/test your code
uv build                                    # 5. (optional) package for distribution
----

This mirrors exactly how `5-mcp-server-deepdive-deployment` in this repo
was set up and used (see its `README.adoc` for the full walkthrough).
